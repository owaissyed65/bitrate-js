# bitrate — React showcase

A Vite + React app that runs the real library in the browser and shows what it produces:
a segment timeline you can click to seek, a player with rendition switching, live job
cards, and security checks run against the running code.

```bash
npm run build --prefix js          # the app loads js/dist
npm install --prefix examples/react-app
npm run dev --prefix examples/react-app
```

Then open http://localhost:5180.

## Tabs

| Tab | Shows |
|---|---|
| **Package a video** | Source metadata, remux or a transcode ladder, segments as a clickable timeline, playback, and every produced file with its playlist |
| **Queue & upload** | Several files at once, with a corrupt one inserted so the skip-and-continue behaviour is visible, plus optional flaky uploads to exercise retries |
| **Resume** | A job interrupted and resumed, checked against an uninterrupted run of the same file |
| **Capabilities** | What this browser supports, and which encoder configurations it actually accepts |
| **Security** | Path-traversal, hostile file names and malformed input, checked live |

Sample videos in `public/` are generated by the test suite; use your own files for a real
test — the generated ones carry synthetic frames that a decoder will reject on playback.

## Appwrite upload

The **Appwrite upload** tab pushes real output to a real bucket. It asks for three values —
endpoint, project ID and bucket ID — all of which are **public identifiers** that ship in
every Appwrite client bundle. They are kept in `localStorage` and never committed.

**Never enter an Appwrite API key.** An API key is a server-side secret with project-wide
scope; a browser has nowhere safe to keep one, and `appwriteAdapter` accepts an
authenticated `Storage` instance rather than credentials precisely so that it cannot.

For the upload to be allowed, the bucket needs Create permission for whichever identity you
use — `Any`, or `Users` with the anonymous-session checkbox ticked.

If the bucket has **File Security** enabled, each created file must also carry its own
permissions, or Appwrite answers `No permissions provided for action 'create'`. Leave the
**public read permission** box ticked: it passes `Permission.read(Role.any())`, which is
also what playback needs, since a player has to fetch every segment.
